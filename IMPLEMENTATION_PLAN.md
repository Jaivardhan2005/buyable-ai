# Seven-day implementation plan

| Day | Objective and exact work | Dependencies, tests, done / do not work on |
|---|---|---|
| 1 | Lock demo script, CSV template, policy form, rubric and ranking formula. Scaffold Next.js/TS/Tailwind/Prisma only after this planning approval. Create schema, auth stub, seed one merchant and 6–10 earbuds. | PostgreSQL decision. Unit-test formula/rubric fixtures. Done: browseable seeded catalog and written demo acceptance checklist. Do not work on LLM or payment. |
| 2 | Build merchant catalog import validation, canonical attributes/inventory, policy form, readiness assessment/issues, safe normalization fixes and report UI. | Day 1 schema. Test malformed CSV, tenant isolation, score fixtures, prohibited fix. Done: upload leads to a persisted explainable score. Do not work on arbitrary documents. |
| 3 | Build buyer session, fixed preference question UI, LLM structured extraction adapter behind feature flag, deterministic filtering/ranking/snapshot and explanation UI. | canonical products. Test repeatable order/ties, budget/stock exclusion, invalid LLM JSON. Done: natural-language prompt produces top 3 deterministically. Do not work on autonomous tool loops. |
| 4 | Implement cart, explicit confirmation summary, guardrail service/state machine, audit events and blocked-stock/limit recovery UI. | buyer flow. Test no payment before confirmation, stale price/stock, policy cap, audit coverage. Done: graceful failure is demonstrable. Do not work on refunds/multi-cart. |
| 5 | Integrate Razorpay test-mode Standard Checkout: order creation, client handoff, server signature verification, transaction/event persistence, idempotency. | test keys/account; verify current docs. Test forged callback, duplicate idempotency key, user cancellation. Done: successful test payment cannot be marked paid without server verification. Do not work on live mode. |
| 6 | Add lightweight verified webhook receiver and reconciliation if environment permits; synchronously verify raw-body signatures, deduplicate provider events, and apply short idempotent state transitions. Complete merchant/customer audit timelines, Buyability Passport, observability/redaction and end-to-end tests. | publicly reachable HTTPS tunnel/webhook config. Test duplicate/replayed webhook and delayed/missed-event reconciliation. Done: full demo has auditable correlation IDs. Do not build a queue, worker, or analytics expansion. |
| 7 | Polish mobile/desktop flows, error states, copy and seed data; rehearse 3-minute demo; record fallback video; security/config review and deploy. | all core paths. Test full happy path plus one blocked and one payment-failure path. Done: fresh-environment runbook and judge-ready demo. Do not add features. |

Daily priority is always: end-to-end path, reliability/payment proof, safety/explainability, visual polish. The MVP uses lightweight synchronous and idempotent webhook handling plus reconciliation, not a queue/worker architecture. If behind, cut policy-text extraction, approval queue, and passport sharing—never deterministic guardrails, confirmation, payment verification, webhook verification/reconciliation, or audit evidence.
