# Database design

Use PostgreSQL, UUID primary keys, `timestamptz` timestamps, `numeric(12,2)` for money displayed in rupees and integer paise (`amount_paise`) for payment arithmetic. All merchant-scoped tables carry `merchant_id`; never trust it from the client.

| Entity | Key fields and types | Relationships, constraints, indexes, validation |
|---|---|---|
| `merchants` | `id uuid`, `name varchar(160)`, `slug varchar(80)`, `status enum`, `created_at` | unique `slug`; active merchant required for publishing/buying |
| `users` | `id uuid`, `merchant_id uuid?`, `email citext`, `role enum(MERCHANT_ADMIN,MERCHANT_EDITOR)`, `auth_provider_id varchar`, timestamps | unique email and provider ID; index merchant; merchant roles only access own tenant |
| `products` | `id uuid`, `merchant_id`, `sku varchar(100)`, `name`, `brand`, `description text`, `price_paise bigint`, `currency char(3)`, `status enum(DRAFT,PUBLISHED,ARCHIVED)`, `source_version int`, timestamps | unique `(merchant_id,sku)`; indexes `(merchant_id,status,price_paise)`; price >= 0; published requires required attributes and inventory |
| `product_attributes` | `id uuid`, `product_id`, `key enum`, `value_json jsonb`, `normalized_score smallint?`, `source enum`, `confidence numeric(3,2)?` | unique `(product_id,key)`; index `(key,normalized_score)`; allowed typed keys only (battery_hours, anc_level, bass, comfort, mic, water_rating); score 0–100; no LLM-created value without merchant approval |
| `inventory` | `product_id uuid PK`, `available_qty int`, `reserved_qty int`, `reservation_expires_at timestamptz?`, `updated_at`, `version int` | `available_qty,reserved_qty >= 0`; `reservation_expires_at` bounds a temporary checkout reservation; version for optimistic locking; decrement/reserve only in transaction and release expired reservations before availability checks |
| `merchant_policies` | `id uuid`, `merchant_id`, `policy_type enum`, `content text`, `structured_rules jsonb`, `status enum(DRAFT,ACTIVE)`, `version int`, `approved_by uuid?` | unique `(merchant_id,policy_type,version)`; index active policies; schema validates max amount/eligible states; active commercial rules require merchant approval |
| `readiness_assessments` | `id uuid`, `merchant_id`, `score smallint`, `rubric_version varchar`, `catalog_snapshot_hash char(64)`, `policy_snapshot_hash char(64)`, `status`, `created_at` | index merchant/time; score 0–100; immutable completed report |
| `readiness_issues` | `id uuid`, `assessment_id`, `code`, `severity enum`, `title`, `evidence jsonb`, `safe_fix jsonb?`, `resolution enum`, `resolved_at` | unique `(assessment_id,code,evidence_hash)`; safe fixes limited by allowlist |
| `customer_sessions` | `id uuid`, `merchant_id`, `token_hash char(64)`, `status`, `expires_at`, timestamps | unique token hash; index expiry; opaque cookie/token only, never raw token stored |
| `customer_preferences` | `id uuid`, `session_id`, `key enum`, `rank smallint?`, `value_json jsonb`, `source enum(USER,LLM_EXTRACTED)`, `confirmed boolean` | unique `(session_id,key)`; rank 1–5; user request/budget must validate before use |
| `recommendations` | `id uuid`, `session_id`, `formula_version`, `request_snapshot jsonb`, `candidates jsonb`, `ranked_results jsonb`, `created_at` | index session/time; immutable, includes product ID/SKU, price and attribute snapshots plus scores; max 3 returned results |
| `carts` | `id uuid`, `session_id`, `status`, `product_id`, `quantity smallint`, `unit_price_paise bigint`, `currency`, `created_at`, `updated_at` | one active cart/session; quantity 1 in MVP; price snapshot nonnegative |
| `transactions` | `id uuid`, `merchant_id`, `session_id`, `cart_id`, `amount_paise bigint`, `currency`, `status enum`, `idempotency_key varchar(100)`, `razorpay_order_id varchar?`, `razorpay_payment_id varchar?`, `confirmed_at`, timestamps | unique idempotency key and provider IDs when non-null; indexes merchant/status/time; amount recalculated server-side; legal state transitions only |
| `payment_events` | `id uuid`, `transaction_id`, `provider`, `provider_event_id varchar?`, `event_type`, `verification_status`, `payload_hash`, `metadata jsonb?`, `received_at` | unique `(provider,provider_event_id)` where provided; append-only; metadata is redacted and excludes secrets/card data; webhook/callback verification recorded |
| `agent_actions` | `id uuid`, `session_id?`, `merchant_id?`, `agent_name`, `action`, `tool_name?`, `input_hash`, `output_hash`, `outcome`, `reason`, `created_at` | index correlation/session/time; audit LLM/tool boundary, redacted payloads only |
| `audit_events` | `id uuid`, `merchant_id?`, `session_id?`, `transaction_id?`, `correlation_id uuid`, `actor_type`, `actor_id?`, `action`, `entity_type`, `entity_id`, `outcome`, `reason`, `metadata jsonb`, `created_at` | append-only; indexes correlation/time, merchant/time, transaction/time; application DB role has INSERT/SELECT only |

Suggested enums live in the ORM schema. Use foreign keys with `RESTRICT` for financial/audit history; archive rather than delete products/policies. Enforce tenant filters in every repository query: `merchant_id` is derived server-side from authenticated merchant membership and is never accepted or trusted from client input. `jsonb` is for versioned evidence/snapshots—not primary query fields. Product attributes used in ranking are additionally constrained/validated in application code. A database transaction covers cart validation, inventory reservation and local transaction creation; external Razorpay calls happen after the local durable intent is recorded, with idempotency reconciliation on retry.

State machines: cart `ACTIVE → CONFIRMED → CHECKOUT_STARTED → COMPLETED|EXPIRED`; transaction `CREATED → PENDING_PAYMENT → AUTHENTICATED → CAPTURED|FAILED|CANCELLED`, with `AUTHENTICATED → CAPTURED` only through verified provider evidence. Never infer payment success from a client flag.
